# Messaging Quotas And Retries

## Contract

Native private sends retain the existing 30-message rolling-minute bound and private invitations the 20-request rolling-day bound. Native room text/action/notice sends share one 30-message actor bound across rooms; room invitation rows and explicitly disclosed abuse reports retain their separate 50-per-day actor bounds. These are existing application safeguards, not newly approved institutional entitlement policy, a combined private/room quota or literal legacy character-window/operator-exemption/automatic-kick parity.

Actor-command transaction advisory locks serialize capacity checks with insertion, audit and receipt/commit. Existing authority, account/consent, contact acceptance, membership, room lifecycle and moderator gates remain required. Identical successful retries are looked up before consuming new capacity, within the existing fresh authority/domain replay boundary; changed commands cannot reuse the successful key. Denied or rolled-back commands must not create a message/invitation/report, write audit or room receipt. Sequence gaps are not business records and are not asserted to roll back.

Private quota cutoffs now use `clock_timestamp()` after command/pair locks, not transaction-start `now()`. New private messages/invitations explicitly record the current database clock. New room invitation rows, including explicit owner participation, also record current invitation time; room sends and reports already use current clock timestamps. Existing records/schema defaults are not rewritten. The bound is based on retained creation/invitation times at domain insertion, not proof of network response time, PostgreSQL commit time, monotonic clocks or cancellation of an already serialized response.

Written message words remain unchanged by an automatic filter. Existing bounded input validation/trimming, output escaping, explicit moderation and safety controls remain. No word rewriting, nickname/presence, plaintext body log, arbitrary redirect or operator quota exemption is introduced.
