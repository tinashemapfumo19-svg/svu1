# Private Message Transaction Authority

## Contract

Private operations retain the router's authenticated personal permission check, then repeat active account, active role, current unended/date-effective assignment and `messages.self` permission checks inside their own transaction. Qualifying account, assignment, role and permission rows are shared-locked through the domain action, audit and commit. Multiple qualifying grants do not stand in for a missing peer: pair eligibility counts distinct qualifying accounts. Both opted-in active/authorized accounts and the existing block/acceptance gates remain required for new correspondence.

All private write transactions acquire one actor-command advisory lock before shared authority locks. This serializes that actor's preference/account-lock upgrades with its send/invite/pair commands. Existing pair, send/invite rate, account/preference and conversation locks remain in place. Preference reads use the same fresh guard; conversation list/summary/history/change reads establish repeatable-read before the guard and content snapshot. Serialization/deadlock conflicts roll back with a coarse 409, not raw PostgreSQL diagnostics. Lost current authority is coarse 403.

Fresh actor authority precedes domain reads, writes and invitation/message retry lookup. An old successful request key cannot bypass lost actor authority. Explicit invitation replay remains retained metadata, not new participation; existing actor preference/block/closed-history rules are not silently changed. Shared grant locks order valid operations before a competing withdrawal; they do not promise to retract a response already serialized or cancel every transport-level session race.

An opted-out/blocked/closed conversation remains readable by its own participant who still has current messaging authority. Peer role/account loss prevents new messages but does not give a third party access or erase the active participant's retained history. Close, decline and block remain safety controls even when the peer is ineligible. No new schema, permission, investigation authority, retention policy, alias or online presence is introduced.
