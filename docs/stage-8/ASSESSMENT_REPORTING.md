## Authority And Selection

Standing staff permissions mirror the native offering view: `teaching.view`, `results.view`, `assessment.plan.manage`, `assessment.marks`, `assessment.review`, `assessment.moderate`, or `assessment.external`. Each permission uses only its own current intake/programme role scopes. Unrelated global roles do not widen access. Allocation-only `teaching.self` users retain their native individual offering workspace; it does not authorize this intake-wide staff aggregate. No new native read/write permissions are granted.

Strict optional selectors are `intakeId`, `periodId`, `courseId` and `format=json|csv`. Intake, period and course combinations must be currently accessible; wrong/private combinations return 404 before mark-sheet reads. Metadata contains only authorized intake/period/course choices. Reports capture one repeatable-read transaction timestamp and query the selected offering pairs in bulk. Selected empty intakes/periods remain explicit custody scopes, rather than losing their authorization binding because there are no report rows.

## Definitions And Controls

- Plans: retained draft/approved/superseded versions and offerings with/without a current approved plan. LMS-only offerings can have no native plan; this is not inferred as overdue work.
- Rosters: active confirmed course enrolments, separated into configured/unconfigured offerings. The structured optional withdrawal marker excludes withdrawn enrolments once the coordinated additive withdrawal schema exists; absent markers describe the existing pre-withdrawal schema. This read does not implement or approve the separate withdrawal workflow.
- Coverage: expected component entries under current approved plans, populated/missing entries and mark/absent/deferred/exempt partitions. Retained current-plan entries outside the active roster remain separate evidence. Native `finalMark` determines calculated/deferred/exempt/incomplete sheet counts; no student identities, raw scores or private notes are returned.
- Submissions: retained statuses under the current approved plan, including returned and deferred-completion superseded records. These are staff mark-sheet submissions, not student hand-ins. Older superseded plan versions are not included in these submission totals.
- Moderation: submitted sheets awaiting internal sign-off, awaiting external sign-off after internal signing, or with required sign-offs ready for review. Changes-requested counts overlap those queues. Hashes, stage order, separate reviewers and absence of prior mark editing are reconciled at the historical decision time; subsequent editing does not retrospectively invalidate an earlier review.
- Recording: approved current all-final sheets versus approved changed/non-final sheets. This is course-level source evidence, not period transfer readiness, a write authorization or official publication. Transferred sheets must reconcile to a same-period retained result batch and matching course/registration/mark rows. Superseded sheets must have the approved deferred-completion origin, matching original plan/submission/hash and independent review/timestamp evidence.
- Freshness: `submissionMatchesSheet` flags changed live source membership or marks without repairing/deleting historical submission evidence. Where the hash and membership still match, calculated final payloads must also agree with the native calculation.
- Age: the maximum elapsed submitted-to-snapshot UTC hours; null when no submitted sheet exists. Totals use a direct maximum, not an average or sum of ages. This is not a business-hours service-level target.

Plan, roster, cell, submission and age controls reconcile the declared partitions. A changed live source is visible workload, not an arithmetic-control failure or permission to transfer it. Invalid source bindings/components/ranges/versions/review custody/recording references fail 409 before returning partial figures. Generation/export audits contain definition version, selection sizes and controls, not scores, student identifiers, reasons, review evidence or source hashes.
