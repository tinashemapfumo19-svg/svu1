# Stage 8 Admissions Reporting

Development implementation of `RPT-01`, `RPT-11` and the roadmap's operational reporting/metric-dictionary requirements. This extends the examination reporting foundation without claiming a Stage 8 exit, approved institutional formulas or statutory applicant headcounts.

## Dictionary And Meanings

The code-owned `admissions-operations-v1` catalogue defines 18 measures with stable IDs, formulas, exclusions, units, filters, refresh policy and proposed Admissions office ownership. All definitions and CSV exports explicitly retain development/owner-approval-pending status. Formula/meaning changes require a new dictionary version; there is no arbitrary SQL/formula editor.

Application records are not unique applicants. The exhaustive current partition is draft, active review, open offer, accepted, rejected, deferred, declined, expired, withdrawn and unclassified submitted. Application status controls draft/withdrawn; submitted records use only their current workflow. Old workflows and decision history do not generate extra applications. Active custom academic stages and information requests count as review. Terminal/reopened outcomes stay with their current state. Deferred applications stay in their original intake; a requested later intake is not a manufactured new application. Withdrawn drafts are included as withdrawn records, even when never submitted.

Accepted-without-conversion is a subset of accepted records, based on the absence of an original `student_programmes.application_id` binding (`origin_programme_id is null`). Conversion is not onboarding completion or active student headcount. Offers-awaiting-expiry is a subset of open offers with an unanswered, overdue offer decision. Reporting never expires offers or changes decisions; an overdue offer still reserves a place until its workflow transition occurs.

Capacity measures reuse the existing intake-capacity SQL formulas: configured capacity; Offer issued/Accepted workflow places plus distinct policy-held transfer arrivals; transfer places; nonnegative remaining places; and places above capacity. Transfers are not invented admissions applications. The existing formula retains transfer arrivals regardless of later programme status and avoids counting arrivals already held through admissions in that intake. Reporting records this policy rather than redefining it. Remaining/over-capacity values are calculated per intake before summing: spare capacity in one intake cannot cancel another's over-capacity condition. This is not a vacancy promise or authority to offer beyond capacity.

## Controls And Authority

- `GET /api/reports/admissions/dictionary`: `admissions.review`; fixed definitions, no applicant/source records.
- `GET /api/reports/admissions/intakes`: the same permission-specific scope; authorized intake metadata only, independently available when operational sources require repair, with a metadata-read audit.
- `GET /api/reports/admissions`: current permission-specific review scope, with optional `programmeCode` and `intakeId` filters.
- `GET /api/reports/admissions?format=csv`: fresh calculation and authority check; JSON envelope with CSV content, filename, source timestamp and definition version for the existing authenticated client.

An unrelated global auditor, academic or results role cannot lend scope to a restricted review role. Authorized intake metadata is selected before any operational source queries. Counts only query those selected intake IDs. Unknown/inaccessible explicit intakes return 404; empty programme selections yield zero totals. Draft, published and closed intakes remain part of the authorized universe, including zero-application intakes. Unknown filters (`asOf`, workflow state, etc.), invalid formats, oversized identifiers and null/newline controls are rejected. Applicant/self-service, decision-only and other domain permissions do not grant this endpoint.

Intake-wide reporting also validates that every selected application has its expected authoritative resource-scope binding. Missing or mismatched programme/intake bindings return a coarse 409 before aggregation, even for a global reviewer; no partial or falsely complete capacity total is silently produced. This is a source reconciliation gate, not a source-repair operation.

One repeatable-read PostgreSQL transaction supplies the generation timestamp, metadata, source counts, capacity and read/export audit. Application counts join only the current workflow; conversion/overdue checks use existence predicates rather than multiplicative decision/programme joins. Two controls verify that application classifications sum to the application-record total and that policy-held places agree with offer/acceptance/transfer counts and the capacity/remaining/over-capacity identity. Each intake is checked before aggregate controls: opposing differences cannot cancel. Unclassified submitted records and source disagreements are shown as review conditions, not invented decisions or silent repairs.

Reports disclose aggregate counts and authorized intake labels/status/capacity, not application/account IDs, applicant identities, answers, contact details, reference numbers, decisions, messages, private evidence or student numbers. Distinct access/export audits carry filters, definition version, timestamp, intake count and control flags, not applicant data. CSV carries the same development status/version/time/filters, units and reconciliation flags, with quoted, formula-neutralized cells. Responses use `no-store`. Exports recalculate, so their snapshot may differ from a previously displayed panel. This is not a retained historical report or as-of reconstruction.

## Workspace And Session Privacy

Admissions staff have an initially collapsed workload panel with authorized intake selection, refresh, grouped application/capacity totals, scrollable intake comparisons, CSV and expandable definitions. If generation fails, authorized metadata remains available to select another intake; the panel shows the source error, suppresses old totals and disables export rather than displaying fabricated zeros. Failed/expired metadata authority never restores private data. The review queue filters are independent from report filters: no queue page limit is treated as an institutional total. Refresh/export is explicit and there is no scheduled/push delivery.

Staff state now uses a generic private-cache reset preserving the in-flight action lock. Sign-out clears private queue, detail, manifest, report, definitions/filter state and stored session before waiting for logout delivery. Bound authenticated 401 responses reset the same state, and responses from a departed session are rejected before assigning private data or downloading a report. MFA partial-session calls remain separate. Detached report/definition toggles cannot overwrite the current panel state.
