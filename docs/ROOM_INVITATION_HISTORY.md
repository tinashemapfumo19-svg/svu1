# Recipient-Aware Invitation History

Memory-model and availability-gated form integration in progress, 2026-10-12. This is not working-backend adoption, rendered browser proof or full legacy coverage.

## Model Contract

`src/room-invitation-history.js` wraps the shared structured history engine rather than duplicating its buffer/navigation rules. Each resource binds an exact room and opaque invitation recipient ID; entries retain only the declared `email` text, not protocol/context/consent fields. Case variants preserve the exact attempted spelling while recipient matching uses canonical case folding. Only addresses from the current user's own attempted invitations appear in the memory-only contact-choice list; it is not a server contact directory, online-user list or a list of successful invitation recipients.

The caller must supply `request`, `current` and `unchanged` functions. `request(email)` must perform the authenticated read-only POST described in `ROOM_INVITATION_CONTEXT.md`; the model does not use fetch or construct URLs. `current` checks bound account/session/room/connected form/native pending state, not the helper's own in-flight flag. `unchanged` checks the captured form values and contact selection before applying results. No caller can omit these checks and still use the model's asynchronous attempt/navigation methods.

Metadata is strictly projected to the six native invitation fields, actor identity and three 43-character opaque values with exactly the `invite` operation. A changed recipient/epoch deletes that resource and refuses the current restoration/recording; a new deliberate attempt is needed. Changed shared authority clears all retained resources and invalidates older outstanding checks. Invalid/foreign context or 401/403 resets all retained authority; recipient 404/409 deletes only matching room/contact resources. Transient quota or other read failures preserve history but cannot restore it without a successful fresh check.

Attempt descriptors are copied before awaiting metadata. Recall requires a bounded exact email draft/selection schema and refuses changed drafts or stale contexts. Navigation returns only editable values/focus/caret, never an old key, revision, recipient ID or epoch. This includes returning an unfinished partial mailbox draft; the draft itself is not an authorized invitation and must undergo a new metadata check on deliberate submission. Clearing a resource removes its remembered address as well as its buffer. Reset/room removal invalidate outstanding reads; an old finalizer cannot unlock a replacement check after reset.

There is one metadata flight per account/room. `busy` and disabled control HTML are available to the future form adapter; clearing and additional attempt/navigation calls are refused during that flight. Native submission/pending/retry remains the caller's responsibility. The model never sends an invitation or returns a replay packet. The caller supplies a freshly generated native-format request key for a deliberate attempt; duplicate frozen keys do not add another entry in the same recipient lifetime. The existing retry path must bypass this model and resend its frozen native packet.

The shared engine bounds each recipient to 25 attempts, 32 resources and 131072 combined retained field code units including draft tails. The separate contact metadata index holds at most 32 latest mailbox strings of at most 254 characters plus fixed-size context data; index entries without retained engine history are pruned, not reconstructed. Clear/forget/reset operate in memory only. No storage, message body, report evidence, consent/disclosure field, provider operation or import is introduced.

## Form Integration In Progress - 2026-10-12

`src/room-invitation-history-ui.js` renders a bounded own-attempt contact picker and shared previous/next/clear controls. Choosing a contact does not overwrite the email draft. Recall requests fresh metadata for that selected contact, restores only email/caret and emits the existing native email input event. A deliberate submission checks the exact current email, generates a new native key and hands only `{email,requestKey}` to the native command constructor. Checking disables picker/command controls while leaving typing available; typing cancels restoration. Unresolved sends block further adapter actions, and the caller's pending retry remains separate. Clear removes the remembered contact without changing the draft.

New backend workspace responses advertise `capabilities.invitationContext:true` as endpoint availability, not authority. Only the existing eligible moderator/creator invitation form mounts the adapter. An older backend without this marker retains its existing native invitation path; an advertising backend cannot fall back to unchecked UI submission if the adapter is unavailable. New scripts load after the shared history engine, and the picker has a constrained 320px/max-100% field width. Controls are inserted after ordinary named-field listeners are bound, so the unnamed history selector cannot become an invitation body or draft field.

`src/messages.js` uses POST with mailbox JSON only. Invitation-context errors are deferred to the adapter rather than invalidating its bound workspace before it can reconcile history. Same-session 400/404/409/429 errors redraw the notice without automatic body reads or unrelated draft loss. On 401/403, protected caches and room history clear; 401 revalidates another available session through the existing identity loader or redraws sign-in. Identity replacement, route departure, access loss and room removal explicitly reset/forget invitation history. These auth/error paths have syntax/scoped binding evidence only; native browser proof remains required.
