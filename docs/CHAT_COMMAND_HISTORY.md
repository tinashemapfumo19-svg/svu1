# Structured Command History

Implementation stage, 2026-10-12. The shared engine and room-definition adapter are implemented and selected native desktop/mobile workflows are verified. This is not full administrative recall completion.

## Contract

`src/chat-command-history.js` supplies an encapsulated memory-only store and native form adapter. An explicit current authority `{accountId,epoch}` owns the store; each resource has an independent key and opaque lifetime epoch. A changed account/session/permission epoch clears all retained intents. Changed resource epochs or lost eligibility clear that resource. Caller adapters must obtain authoritative fresh epochs: a caller-supplied identifier is not itself proof of a target's lifetime or permission.

Only declared text/choice fields can be retained. Shapes, names, limits and current option sets are checked; transport metadata, revisions, request keys as editable fields, consent/disclosure and preference switches are excluded. Exact typed values are not trimmed, parsed as commands or automatically executed. Frozen request identities deduplicate retained attempts; returned recall values contain no request identity, authority, target transport or revision.

Bounds are 25 entries per resource, 32 resource slots, 16 fields, 8192 code units per intent and 131072 total retained value code units including the saved unfinished tails. Least-recently-used slots and oldest entries are evicted as necessary. Navigation preserves the original unfinished fields and focus/selection even at the total-memory boundary. Clearing history leaves the live form draft untouched. Route/session owners must discard/reset the store on departure.

The form adapter uses explicit icon controls, not intercepted arrow keys. Recall first awaits the adapter's read-only authority refresh. It refuses disconnected, busy/frozen, disabled or changed account/session/resource controls and rechecks the current field schema/options. If editable values change during that await, restoration is cancelled without moving history position or overwriting the new input. Submit controls and capture-phase submission are blocked while the check is in flight. Editable focus/selection is remembered before button focus transitions. Restore emits only local input events and focus/selection changes. The adapter never submits the form, calls a transport directly, stores plaintext outside memory or changes disclosure checkboxes. Explicit submission remains a separate native operation with current revisions, fresh confirmations and a newly generated request identity.

## Room Creation

`message-rooms.js` connects history to the four native room-definition fields: title, purpose, policy reference and retention rule. Initial room loads for managers fetch authenticated `/api/chat-command-context`; every recall navigation fetches that metadata again through the current native session. The context must belong to the room workspace's current account. A changed epoch clears retained definitions; revoked/regranted assignments cannot restore old attempts even if their IDs are retained.

Creating a new room has no pre-existing peer, member, message or case target. Its history resource is `room:create`, with the current account/session/permission epoch. This is not a substitute for those target-specific lifetime checks on other commands. The existing room-create endpoint still validates current authority and definition fields. The existing frozen retry packet is retained and history controls are disabled while it is unresolved. A deliberate recalled submission gets a new native request key; retrying the packet does not add another history entry.

The store lives in room workspace state; account/session and route departure explicitly reset it before discarding that state, and room access cleanup resets it even if detached controls still reference the store. Lost management capability resets it. No migration, working-data fixture, role appointment, provider enablement, archive execution or import is needed for this UI stage.
