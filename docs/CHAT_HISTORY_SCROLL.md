## Native Contract

- Valid private/room participant contexts have a keyboard-focusable ordered message pane with a 50dvh maximum, native overflow, stable scrollbar space and visible keyboard focus. Deployment meta `svu-chat-history-height` accepts integer pixel strings from 120 through 900; absent/malformed settings use the public 440-pixel default, and an explicitly empty setting uses the 300-pixel stylesheet fallback. Arbitrary CSS strings/units are refused. Controls, composers, consent and independent safety cases stay outside the pane. No message text is replaced or newly persisted.
- The first view of each bounded history page starts at its bottom. Later redraws/refreshes restore that page's actual pixel position. Each context retains at most eight LRU page snapshots; each stores only a bounded numeric cursor key, pixel offset and highest seen message position. Existing eight-tab and thirty-record history limits remain. Closing/discarding a context, authority/consent/membership replacement, actor departure, route departure or reload drops its scroll metadata with the existing context lifecycle.
- Incoming newly rendered rows advance the cached offset by their actual native row heights, clamped to the pane extent, whether the reader was at the bottom or reading earlier. Own messages and room action/notices also advance. Highest-position tracking uses exact signed PostgreSQL bigint bounds rather than lossy JavaScript numbers. Refresh/replayed rows, formatting changes and moderation of existing rows do not constitute new batches or repeatedly advance the pane.
- A background tab retains its own page/offset/high-water state without fetching private message bodies for hidden tabs. When selected, its authorized current page supplies the deferred rendered batch. Thread/workspace minimization also defers movement until restored, including a refresh/poll that replaces the hidden DOM. Only rows in the bounded newly rendered page contribute heights; no unseen/pruned record body or arbitrary historical batch size is inferred.
- Pixel offsets/extents are capped at 10000000. Keys/positions are validated, pages above thirty input records are refused, and malformed positions cannot become a high-water mark. Cleared rows still contribute to the complete authorized page's high-water mark, so restoring previously displayed records is not mistaken for new messages. An empty local clear clamps the offset to zero; restoration starts there without replay advance.
- Capture runs before root replacement and before hiding a pane. A WeakMap associates the live DOM pane with its snapshot and context/session guard. Detached, hidden, zero-height or revoked panes cannot overwrite cached pixels; stale scroll events cannot mutate or revive a disposed context. There is no persistent DOM/body cache, browser storage, delayed timer or synthetic keyboard interception. Native list scrolling does not steal textarea Up/Down/Tab.
- Focused-pane keyboard focus survives an ordinary redraw/refresh only for the same selected participant context, without moving the document or pane. Identity/route departure clears the pending focus reference; replacement/revocation cannot focus another context or a hidden pane. This does not override explicit user navigation to other controls.
- Scrolling, restoration, toggles and local minimization do not send messaging commands, acknowledge reads, change participation or mutate frozen requests. Explicit user sends and existing explicit read controls remain their own commands. Native pagination/display clearing is not legacy storage pruning or an institutional retention policy.
