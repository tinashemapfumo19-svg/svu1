# Native Chat Alerts

Implementation register, 2026-10-12. User decisions: sound starts off until enabled; own messages retain legacy alert behavior. Account names, no presence/aliases, and exact written messages remain unchanged.

## Contract

- Private and institution-wide room tabs poll only participant-authorized activity metadata for background alerts. At most 16 open contexts are checked every five seconds; requests are single-flight and abort on departure. No background bodies, automatic read acknowledgements, directory/presence publication or alert-delivery writes are introduced.
- The alert controller never requests bodies. Existing foreground refresh of the selected context is retained, including a selected collapsed/minimized workspace and explicit user refresh. Inactive-window/document-hidden automatic body polling is suppressed; nonselected tab alert polling does not load those tab bodies. Alert badges are not read receipts or a replacement for explicit unread handling.
- Initial, reset and repeated cursors are silent. Cursor account/type/recipient binding is checked before consuming exact bigint counts. Selected visible contexts clear their badges; inactive windows gain a generic count-only title. Hidden/minimized contexts retain independent badges and a generic pending count outside the collapsed workspace.
- Window alerts, sound and own-message inclusion are independent controls. Only three bounded boolean preferences persist under the verified account ID. Defaults are window on, sound off and own messages included; index meta settings configure defaults. No message, cursor, count, draft or session key is newly persisted.
- Sound uses a brief generic Web Audio tone, requires a trusted user gesture and respects mute/window controls. Test sound changes no server data. Unsupported or blocked audio reports its state without breaking messaging. No Flash, evaluated timers or global cross-account cookies are used.
- Keyboard, pointer, focus and document visibility handle local attention, not online presence. Badge slots have stable dimensions and respect reduced motion. Titles contain no people, room names or private words.
- Context removal, access refusal, identity/session changes and route departure clear stale counts, timers, requests, title and audio. In-flight response checks bind generation, account, context reference, cursor and preference version. Repeated identical errors notify once until recovery; changing own-message inclusion establishes a fresh silent baseline.

## Boundaries

Alerts operate while the authenticated messaging workspace is mounted, not as system/push notifications or across a closed browser. Background timer throttling and device/browser sound permissions remain external. Browser graph execution does not prove audible physical speaker output. Snapshot-time backend authority cannot certify a later concurrent policy change.

Native browser checks use desktop and mobile-viewport Chromium projects, not physical handsets. Inactive-window/document-hidden alert behavior uses controlled visibility/focus events to avoid background timer throttling; real OS minimization/suspension and hardware audio remain separate checks.

The full legacy goal remains active: broader current presentation/authority/report regression, structured administrative-command recall/replay, translations/themes/configured catalogues, CMS extraction and institutional policy/key/retention/import requirements remain separate. Existing shared user edits are preserved. The unchanged final guard certifies that run's snapshot, not that the user has finished editing.
