# Current Session Principal

## Contract

Request authentication obtains session state, account eligibility, active-factor status, current role risk, scoped roles and their permissions in one PostgreSQL statement snapshot. Role assignments qualify only when the role is active, the assignment is unended, its start date has arrived and its optional end date has not passed. The lateral role aggregate retains each assignment's own scope and permission set, including qualifying roles without permissions. The flat permission list is deduplicated from exactly those scoped roles; a global unrelated role cannot lend scope to a different permission. Empty grants do not invalidate authenticated self access, but authorize no protected permission.

The current MFA requirement is evaluated before returning the principal. Existing enrolled/privileged/off policies, assurance checks and partial-session endpoint boundaries remain unchanged. Login MFA context now applies the same active/unended/date-effective role filters. Account, session expiry/status and active-factor checks are retained. No new role, permission, migration or institution-wide MFA policy is introduced.

This is a coherent request-authentication snapshot, not transaction-long shared authority locks for every downstream command, cancellation of a response already serialized or a claim that password verification, session creation and all subsequent business statements share one transaction snapshot. Private/room/fleet transaction guards remain separate protections. Concurrent withdrawal after a principal snapshot can affect the next authentication; command-specific fresh authorization and revocation ordering still need their own evidence.
