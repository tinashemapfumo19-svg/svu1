# Stage 7 Examination Publication Editions

Development extension of `EXM-03` to `EXM-05`, `EXM-19` and the roadmap's controlled publication/history requirements. New timetable publication no longer destroys the only retained copy of the preceding edition. This is traceable operational history, not an approved retention duration, legal-hold/disposal policy or a signed institutional archive.

## Capture And Migration

Migration `060_exam_publications.sql` creates immutable period/revision editions. The existing publication transaction stores a complete edition after student/staff snapshots, manifests and frozen candidate-account bindings have been finalized, before notifications and commit. Failed validation or a later transaction failure leaves no edition. A unique period/revision key prevents duplicate capture; updates/deletes are refused by an append-only database trigger.

New editions retain the exact timetable, published duties, frozen room manifests, publisher/preparer references, timestamp, reason and period/programme/intake labels observed by that publication. Changing current metadata does not rename a newly captured historical edition. Authorization still uses the period's current authoritative programme/intake scope, not the historical display label. A canonical SHA-256 checksum binds the stored source content and provenance; recursive key ordering makes it stable after JSONB serialization. It is a consistency checksum, not a digital signature.

Migration copies only each existing last-published snapshot, including one retained while the timetable is currently draft. It marks these rows `retained`. Display labels are those available at migration; they are not claimed to be recovered historical labels. If an intervening draft replaced `prepared_by`, migration leaves the old preparer unknown rather than attributing the preceding publication to the later editor. Earlier overwritten editions are not reconstructed from current enrolments, sitting-change history or present arrangements. A retained legacy edition without a frozen manifest remains readable as a timetable but cannot produce a historical candidate roster.

Edition storage has the same confidential internal participant bindings as the existing published snapshots. APIs explicitly whitelist output: summary/detail responses omit candidate lists, private case evidence, staff/account IDs and candidate-account bindings. Frozen manifests expose the existing shared operational candidate fields to scoped officers, not private arrangement requests/reviews. Inappropriate sensitive text entered in a publication reason or operational instruction is not automatically detected.

## Historical Seating

Timetable editions are immutable before optional seats may be published. [Seating publication history](EXAM_SEATING.md) is therefore a separate source: a historical manifest can select a published seating revision that pins that exact timetable publication and manifest checksum. Draft seat entries and seating from another edition never populate it. The default is that edition's latest published seating event, including full withdrawal; `seatRevision=0` explicitly displays the original unseated manifest. An explicitly selected export re-fetches that exact seating edition, not whatever later seat plan became current.

Current timetable cancellation, draft changes, late enrolment or revoked/replaced duties do not rewrite historical editions. Historical access does not authorize current duties, paper downloads, arrangement approvals or new seating mutations. Live endpoints keep their existing fail-closed draft/source/assignment rules.

## Authority And Interface

| Endpoint | Authority |
| --- | --- |
| `GET /api/exams/publications?q=&limit=&offset=` | Scoped `exams.schedule` or `exams.publish`; literal programme/intake/period search, scope-filtered pagination/counts |
| `GET /api/exams/periods/{id}/publications/{revision}` | Current permission-specific office scope; whitelisted historical timetable/duties and checksum |
| `GET /api/exams/periods/{id}/publications/{revision}/sittings/{sittingId}/manifest?seatRevision=` | Same office scope; exact frozen roster and optional exact published seating edition |

Search is bounded to 100 characters, pages to 1-100 records, offset to 1000000 and publication/seating revisions to database integer bounds. Search treats `%` and `_` literally. Scope filtering precedes pagination and total counts. Only metadata is fetched for the index, not whole snapshots. Historical detail/manifest access is audited with revisions/source checksums, without candidate numbers, seat labels or case evidence. Responses retain `no-store`. Metadata enumeration currently filters an ordered result set in memory, following the existing scoped-history pattern; production-volume indexing/load testing remains a gate.

Registry has a searchable publication-history index independent of the current timetable. Read-only edition panels show frozen labels, publication reason/date, sitting counts and published invigilator names. Frozen manifest buttons open clearly labelled historical views, with a historical seating selector and CSV download carrying edition/manifest/seating provenance. Downloads reauthorize through the historical endpoint. Closing a publication also clears its manifest. Generic Registry sign-out/session-loss reset and departed-session response rejection cover the new caches.

Historical office access requires current scoped scheduling/publication authority. Results-view, arrangements-only, duties-only and student permissions do not grant this new office-history endpoint. This slice does not introduce historical student/invigilator self-service or grant former assignment access; any such extension needs explicit retained-ownership/assignment rules and verification. The existing current own timetable/duties workflow remains separate.
