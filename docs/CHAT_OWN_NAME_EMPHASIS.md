# Native Own-Name Emphasis

Implemented and verified 2026-10-12. Eight focused units, four corrected focused native cases and the final 621-unit/28-browser/22-smoke aggregate pass. This matches reader-name presentation, not structured mentions, account aliases, presence or notification delivery.

## Source Boundary

Read the active nickname-emphasis path in the supplied public `pfcclient.js` `parseMessage`. Its case-insensitive escaped-nickname pattern uses start/end or space/comma/colon/semicolon delimiters after BBCode/smiley processing, and replaces matched spelling with the configured nickname. No archived script/configuration/history was executed or imported. Native account names replace room nicknames according to the user's decision, and original message spelling/case is preserved instead of rewritten.

## Native Contract

- A separate per-conversation/per-room Emphasize my name checkbox is default-off, independent of formatting and smileys. It is in-memory only and drops with reload, actor departure, authority/context disposal or participation replacement. No cookies, display-name input, room aliases, nickname completion, directory query or online/presence signal is added.
- The reader name comes only from the authenticated `/api/identity/me` response's `person.preferredName`, with a validated account identifier. It is bounded to 200 characters, trimmed for name matching and refused if empty, malformed or containing ASCII control characters. Legal name, email and client/session labels do not substitute. A missing/invalid preferred name disables emphasis and cannot reuse a previous name.
- The self-profile is refreshed through the common loader and explicit private/room refresh paths. The first validated same-token account ID remains pinned. An invalid or unexpectedly changed ID clears private/room content, histories, cached name and the writable presentation identifier before refusing the load; a new session/binding resets the pin. No other account's private data is requested to resolve a name.
- Literal regex punctuation is escaped, and Unicode case-insensitive matching preserves the actual matched message text. Start/end and native whitespace/comma/colon/semicolon boundaries prevent ordinary substring matches. Native newline/Unicode whitespace is supported because messages no longer discard newlines. Adjacent occurrences are all handled rather than consuming the next delimiter.
- Contiguous AST text tokens are coalesced for multiword names without reducing the original visited-node count. Matches do not cross formatting/tag boundaries. HTTP(S) chunks, literal angle-bracket tag syntax, generated attributes and formatted link labels are not emphasized. Names themselves remain escaped literal text inside a fixed strong marker, never HTML or an image substitution.
- Existing 4000-character input, 1024-node/depth-12 AST and 32000-character formatted-output limits remain; at most 128 own-name markers are generated per message. Unsafe/malformed/recovered BBCode or any exceeded limit falls back to the complete escaped literal body, with no partial replacement.
- Stored message bodies, request keys/receipts, composer drafts/carets/history, read acknowledgements, consent and report/safety evidence are not changed by the display toggle. Report bodies/reasons remain escaped literal even when history emphasis is enabled. This is not a notification/mention-routing mechanism or an identity-edit/approval workflow.
